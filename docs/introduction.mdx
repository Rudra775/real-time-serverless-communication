## The Problem

Traditional WebSocket architectures break in modern cloud environments:

<AccordionGroup>
  <Accordion icon="link-slash" title="Sticky Sessions Required">
    WebSockets need the same server for the entire connection. Load balancers must route based on connection state, not load.
  </Accordion>

  <Accordion icon="server" title="Stateful Servers">
    Each server holds connection state in memory. Scaling down means lost connections.
  </Accordion>

  <Accordion icon="ban" title="Serverless Incompatible">
    AWS Lambda, Cloud Run, and similar platforms cannot maintain long-lived connections.
  </Accordion>

  <Accordion icon="triangle-exclamation" title="Complex Failover">
    When a server crashes, all connected clients disconnect and lose queued messages.
  </Accordion>
</AccordionGroup>

## The Solution

This engine decouples connection state from the server using:

<CardGroup cols={3}>
  <Card title="Server to Client" icon="arrow-right">
    Server-Sent Events (SSE) for efficient one-way streaming
  </Card>
  <Card title="Client to Server" icon="arrow-left">
    HTTP POST for stateless message ingress
  </Card>
  <Card title="Sync and State" icon="database">
    Redis Pub/Sub + Lists for synchronization and durability
  </Card>
</CardGroup>

<Check>Horizontal Scalability - Add instances without reconfiguration</Check>
