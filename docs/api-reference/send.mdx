## Overview

Publishes a message to Redis. If `to_user` is specified, the message is saved to that user's Inbox AND broadcast. If omitted, the message is only broadcast to currently connected clients.

## Endpoint
POST /send

## Request Body

<ParamField body="message" type="string" required>
  The message content to send
</ParamField>

<ParamField body="to_user" type="string">
  Target user's ID. If provided, message is saved to their Inbox for reliable delivery.
</ParamField>

<ParamField body="..." type="any">
  Any additional fields you include will be passed through in the payload
</ParamField>

## Response
Message sent

## Examples

<CodeGroup>
```bash cURL (Direct Message)
curl -X POST http://localhost/send \
  -H "Content-Type: application/json" \
  -d '{
    "message": "Your order has shipped!",
    "to_user": "user_123"
  }'
```
```bash cURL (Broadcast)
curl -X POST http://localhost/send \
  -H "Content-Type: application/json" \
  -d '{
    "message": "System maintenance in 10 minutes"
  }'
```
```python Python
import requests

# Send to specific user (reliable)
response = requests.post('http://localhost/send', json={
    'message': 'You have a new message from Alice',
    'to_user': 'user_456',
    'notification_type': 'chat',
    'sender': 'alice_789'
})

# Broadcast to all connected clients
response = requests.post('http://localhost/send', json={
    'message': 'New features are now available!',
    'type': 'announcement'
})
```

## Implementation Details

From the source code:
```go
// 1. Check if this is a Direct Message
targetUser, _ := payload["to_user"].(string)

msg := engine.Message{
    Type:    "broadcast",
    Payload: marshalPayload(payload),
    RoomID:  "general",
}
data, _ := json.Marshal(msg)

// 2. If for specific user, save to inbox
if targetUser != "" {
    redisBroker.SaveMessage(ctx, targetUser, data)
}

// 3. Publish for real-time delivery
redisBroker.Publish(ctx, "general", data)
```

<Info>
Messages are stored in Redis Lists with a 24-hour TTL: `inbox:user_id`
</Info>

## Broadcast vs Direct Message

| Feature | Broadcast (no `to_user`) | Direct (with `to_user`) |
|:--------|:-------------------------|:------------------------|
| Persistence | No (fire-and-forget) | Yes (Inbox Pattern) |
| Offline Users | Don't receive | Receive on reconnect |
| Use Case | System alerts, tickers | Notifications, messages |

<Warning>
For important messages, always include `to_user` to ensure delivery even if the user is offline.
</Warning>
