## Overview

Clears all pending messages from a user's Inbox in Redis. Call this after the client has successfully received and displayed all backlog messages.

---

## Endpoint Configuration

* **URL:** `/ack`
* **Method:** `POST`

---

## Request Body Fields

<ParamField body="user_id" type="string" required>
  The unique identifier of the user whose inbox should be cleared.
</ParamField>

<ParamField body="token" type="string">
  The client's signed JWT token. Required if `JWT_SECRET` is configured (unless bypassed by `X-API-Key`).
</ParamField>

---

## Authorization Modes

### 1. Client-Side JWT Validation (Production)
If `JWT_SECRET` is enabled, the gateway validates that the JWT signature is correct and that the user inside the token matches `user_id`.

```javascript
await fetch('http://localhost/ack', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    user_id: 'user_123',
    token: signedJWT
  })
});
```

### 2. Backend Server Bypass
If a secure backend needs to clear a user's inbox, it can bypass the JWT check by sending the gateway API key in the `X-API-Key` header:

```bash
curl -X POST http://localhost/ack \
  -H "X-API-Key: your_secret_key" \
  -H "Content-Type: application/json" \
  -d '{"user_id": "user_123"}'
```

---

## System Behavior

Upon receiving a valid request, the server executes a Lua script atomically in Redis:
1. Fetches all pending messages stored in `inbox:{user_id}`.
2. Deletes the Redis key `inbox:{user_id}`.
3. Returns the list of cleared messages.

This prevents redundant message delivery and memory bloat on connection reconnects.
